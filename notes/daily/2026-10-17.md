### 4. [Four evaluation engineering lessons learned from building agent plugins](https://cloud.google.com/blog/topics/developers-practitioners/four-eval-engineering-lessons)

Google Cloud 官方博客分享在构建 AI 编码 Agent 插件（Google Cloud Developer plugin）过程中总结的四条评估工程经验，核心观点是衡量 Agent 行为比构建更难。首条经验指出：不应让 LLM-as-judge 只看最终文本总结打分，而应对工具调用与执行步骤逐级评分，因为 grader 看不到 Agent 实际做了什么，导致初始测试集中三条实际通过的用例被误判为失败。

- 来源：Google Cloud AI and Machine Learning Blog | 2026-10-17 00:00 | 重要性 4/5 | 可信度 5/5
- 标签：Agent、Eval、评估工程、LLM-as-judge、工具调用、Coding Agent、Google Cloud
- 为什么看：来源为 Google Cloud 官方博客，可信度高；主题直击 Agent 评估工程（Eval）这一用户高偏好方向，且以真实插件开发为案例，提供可落地的反模式经验（按执行步骤而非最终总结评分），对自建 Agent 评估体系有直接参考价值，值得精读。

### 5. [Quoting Addy Osmani, Morgan Westlee Lunt, and Qing Wang](https://simonwillison.net/2026/Oct/16/code-review)

Simon Willison 引用 Anthropic Claude Code 团队博客观点：与其用『人是否读过代码』作为审查代理，不如追问『这次改动可能出什么问题、该由哪种检查来兜住』。这把审查从终点关卡变成持续过程，类似拼写检查，多数常规改动先由 Claude 审查修复后再交人工，从而把团队注意力留给更高层问题。
